📋 เกณฑ์ตรวจจับและวิธีการ

BBL Migration Parity Checker · อธิบายทุก check ที่เครื่องมือใช้ตรวจ + วิธีการ + เกณฑ์ผ่าน/ไม่ผ่าน

1. การให้คะแนน Parity Score

แต่ละหน้าจะได้ Parity Score (0–100%) คำนวณจาก 12 checks ใน 5 groups ผ่านเมื่อ ≥ 85%

เกณฑ์ชุดนี้ออกแบบตาม defect ที่ QA เจอซ้ำจริง — เนื้อหาหาย, รูปหาย, การจัดวางเพี้ยน, ลิงก์ดาวน์โหลดพัง — น้ำหนักจึงเทไปที่ 4 กลุ่มแรก ส่วน structure เหลือ 10%

Checkน้ำหนักเกณฑ์ผ่านวิธีคำนวณ
Missing content — 30%
Content length (เนื้อหาหลัก)13%AEM อยู่ใน ±30% ของ prodเทียบความยาวข้อความเฉพาะเนื้อหาหลัก — ตัด header/footer/menu และบล็อกที่ไม่ถูก render (prod ฝัง modal ซ่อนไว้ในหน้า ซึ่งเคยทำให้ตัวเลขพองกว่าจริง 4 เท่า)
Missing text (ระดับประโยค)17%ไม่มีประโยคหายตัดข้อความที่มองเห็นของ prod เป็นประโยค (≥60 ตัวอักษร) แล้วหาว่ามีอยู่ใน AEM ไหม — เทียบแบบไม่สนช่องว่าง จึงไม่ขึ้นกับว่าใครใช้ <p> หรือ <table>
Missing assets — 25%
Missing image12%จำนวน ≥ 80% ของ prodนับรูปในเนื้อหาหลัก รวม CSS background-image ไม่ใช่แค่ <img> — prod เสิร์ฟรูปเนื้อหาเป็น background เป็นส่วนใหญ่ ถ้านับแต่แท็กจะมองไม่เห็น
Broken image (ฝั่ง AEM)13%ไม่มีรูปที่โหลดไม่ขึ้นรูปบน AEM ที่แท็ก render แล้วแต่ไฟล์โหลดไม่สำเร็จ (naturalWidth 0 ทั้งที่ complete แล้ว) — ยกเว้น .svg และ data: URI รูปที่ยังโหลดค้างอยู่ไม่นับว่าพัง
Content alignment — 20%
Content order10%ลำดับตรง ≥ 90%บล็อกข้อความที่มีทั้งสองฝั่งต้องเรียงลำดับเดียวกับ prod (หาด้วย LIS)
Visual layout (column profile)10%โปรไฟล์ตรง ≥ 85%เทียบการกระจายเนื้อหาแนวนอนจาก screenshot — normalize แล้วจึงไม่ขึ้นกับความสูงหน้า และซ่อน cookie banner ก่อนถ่ายเพื่อไม่ให้ overlay ถูกนับเป็นความต่างของ layout
Download links — 15%
Download links present9%ครบทุกไฟล์ไฟล์ .pdf/.doc/.docx/.xls/.xlsx/.zip ของ prod ต้องมีบน AEM (เทียบจากชื่อไฟล์)
Download links alive6%ไม่มีลิงก์ตอบ ≥ 400HEAD check ลิงก์ดาวน์โหลดบน AEM จาก cache — ถ้ายังไม่มีข้อมูล check นี้จะถูกกันออกจากคะแนน ไม่ใช่ตัดสินว่าตก
Structure & template — 10%
Headings (Jaccard)4%Jaccard > 0.6เปรียบเทียบชุด heading text ด้วย Jaccard index
Links match2%match > 50%เปอร์เซ็นต์ของ link text ใน prod ที่พบใน AEM
Meta tags2%ตรงครบ 4 รายการ (partial credit)คิดคะแนน: title, description, ogTitle, ogImage — og:image เทียบว่ามี path ทั้งสองฝั่งเท่านั้น เพราะสองระบบเก็บไฟล์คนละที่และ AEM ตั้งชื่อเป็น hash · แจ้งเฉยๆ ไม่คิดคะแนน: keywords · canonical ถูกตัดออกทั้งหมด
Template (component ในหน้า)2%component แต่ละ type ≥ 80%เทียบ accordion/table/form/video เฉพาะในเนื้อหาหลัก — header/footer เป็น chrome ระดับเว็บ ย้ายไปรายงานครั้งเดียวบน dashboard
Partial credit: แม้ check ไม่ผ่าน ก็ยังได้คะแนนบางส่วนตามสัดส่วน (เช่น headings ที่ Jaccard 40% ได้ 40% ของน้ำหนักตัวเอง)
ข้อมูลไม่พอ = ไม่ตัดสิน: check ที่ไม่มีอะไรให้เทียบ (เช่น ทั้งสองฝั่งไม่มีไฟล์ดาวน์โหลด) จะถูกกันออกจากทั้งตัวตั้งและตัวหาร ไม่ใช่นับเป็นตก — หน้านั้นจึงไม่ถูกลงโทษเพราะไม่มีของให้ตรวจ
สิ่งที่ถอดออกจากการคิดคะแนน (เพราะสองระบบเทียบกันไม่ได้จริง ไม่ใช่เพราะเว็บผิด):
  • Image alt text — prod เขียน alt เป็นไทย AEM เป็นอังกฤษสำหรับรูปเดียวกัน และ prod ไม่ได้ใส่รูปเนื้อหาเป็น <img> เลย ทำให้ AEM ที่ทำ alt ดีกว่ากลับได้ 0%
  • Image distortion / ratio — AEM ตั้งชื่อไฟล์เป็น hash จับคู่รูปตามชื่อไม่ได้ ต้องจับตามลำดับ ซึ่งเอารูปคนละรูปมาเทียบสัดส่วนกัน
  • Header / footer menu — เป็น chrome ระดับเว็บ เหมือนกันทุกหน้า ย้ายไปรายงานครั้งเดียวใน panel Site chrome บน dashboard
  • canonical — คนละโดเมนโดยธรรมชาติ · keywords และ Thai/English balance เหลือแค่แจ้งเตือน ไม่คิดคะแนน

2. การตรวจจับ Error Pages (ไม่นับเป็น parity)

หน้าที่เป็น error จะ parity = 0% ทันที ไม่เทียบต่อ — เพราะไม่มีเนื้อหาให้เปรียบเทียบ

สถานะBadgeวิธีตรวจจับความหมาย
AEM 404 AEM 404 title มี "404" หรือ "not found" หรือ body มี "ไม่พบหน้าที่คุณต้องการ" หน้ายังไม่ถูก migrate — URL มีใน prod แต่ AEM ยังเป็น 404
PROD 404 PROD 404 title มี "404" หรือ "not found" หรือ body มี "ไม่พบหน้าที่คุณต้องการ" (ฝั่ง prod) ต้นฉบับหายไป — URL อาจถูกลบจาก production แล้ว ไม่มีอะไรให้เทียบ
BOTH 404 BOTH 404 ทั้ง prod และ AEM เป็น 404 URL ไม่มีอยู่จริง — อาจเป็น URL เก่าใน sheet ที่ถูกลบไปแล้ว
BLOCKED BLOCKED title มี "Access Denied" / "Forbidden" / "Blocked" หรือ body มี access-denied text ถูก WAF/anti-bot block — prod ปฏิเสธการเข้าถึง ต้อง re-capture ภายหลัง (อาจเป็น rate limit ชั่วคราว)

3. การตรวจจับเพิ่มเติม (Additional Issues)

นอกเหนือจาก parity score ยังตรวจหาปัญหาเฉพาะด้าน — นับเป็น "issues" ไม่กระทบ score โดยตรง แต่แสดงใน drill-down

🇹🇭 Thai/Latin Script Ratio

จุดประสงค์: ตรวจจับหน้าที่ AEM แสดงผิดภาษา (แสดงภาษาอังกฤษแทนไทย)
วิธีการ: นับตัวอักษรไทย [\u0E00-\u0E7F] เทียบกับ Latin [A-Za-z] คำนวณ ratio = Thai / (Thai + Latin) ของทั้ง prod และ AEM
เกณฑ์ flag: ถ้า |prod ratio - AEM ratio| > 0.1 (10%) = ปัญหาภาษา
ตัวอย่าง: prod 98% Thai vs AEM 82% Thai → delta 16% → flag High severity

🔗 Broken Link Detection

จุดประสงค์: ตรวจจับ links ที่ migrate แล้วพัง (HTTP error)
วิธีการ: fetch แต่ละ link ในหน้า AEM จากใน browser เดียวกัน (in-browser fetch ผ่าน WAF ได้) — ใช้ HEAD ก่อน ถ้า 405/501 ใช้ GET แทน ทำเป็น batch ละ 5 ตัว
ขอบเขต: เช็คสูงสุด 30 links/หน้า (เฉพาะ same-origin AEM links เพื่อหลีก CORS)
เกณฑ์ flag: HTTP status ≥ 400 = High (broken), status 0 = Medium (unreachable/CORS)

🔢 Dynamic Block Filter

จุดประสงค์: ลด false positive จากเนื้อหาที่เปลี่ยนทุกวัน (วันที่, อัตราดอกเบี้ย, counter)
วิธีการ: กรอง text block ออกก่อนเทียบ content ถ้า:
  • สัดส่วนตัวเลข > 40% ของตัวอักษรทั้งหมด (เช่น "ดอกเบี้ย 2.75% ต่อปี")
  • ตรงกับ regex เดือนไทย + ปี (เช่น "ม.ค. 2568", "ธันวาคม 2567")
ผล: block เหล่านี้จะไม่ถูกนับเป็น "missing text" แม้ prod/AEM จะต่างกัน เพราะเป็นข้อมูลที่คาดว่าจะเปลี่ยน

🛡️ AEM-specific Issues

Leaked /content/ paths: ตรวจหา AEM internal JCR paths (เช่น /content/bangkokbank/th/locate-us) ที่หลุดสู่ HTML แทนที่จะเป็น clean URL — บ่งบอก Sling Mapping ยังไม่ตั้งค่า
Missing features: เปรียบเทียบ features ระหว่าง prod และ AEM — login button, language switcher, social icons (Facebook/Line/X), cookie banner

5. ข้อจำกัดและข้อควรทราบ

  • Parity score เป็น heuristic — ไม่ใช่ pixel-perfect diff ใช้ set-membership + threshold ไม่ใช่ diff algorithm อย่าง LCS
  • Link matching ใช้ text ไม่ใช่ href — เพราะ prod ใช้ /th-TH/Personal/... ส่วน AEM ใช้ /th/personal/... (different URL pattern)
  • Image matching ใช้ order-based — เพราะ AEM hash filenames ทำให้ filename matching ไม่ work อาจ match ผิดถ้าลำดับรูปเปลี่ยน
  • AEM client-render ช้า — บางหน้าต้องรอ layout settle นานถึง 18 วินาที ทำให้ capture ช้ากว่า prod
  • WAF block เป็นชั่วคราว — หน้าที่ BLOCKED สามารถ re-capture ใหม่ได้ (อาจผ่านในรอบถัดไป)
  • Dynamic content กรองได้ไม่หมด — filter ครอบคลุมตัวเลข > 40% และเดือนไทย แต่ข้อมูลแบบอื่น (เช่น ชื่อผู้บริหารที่เปลี่ยน) ยังนับเป็น missing
  • Broken link check เช็คเฉพาะ same-origin — cross-origin links จะได้ status 0 (CORS) ไม่สามารถเช็คได้จากใน browser
